This folder explains how the X Store codebase is put together and how a download moves through the app. The docs focus on the project-owned code and the glue that makes the embedded libraries work on Xbox 360.

The ATG framework under `Common/` is intentionally not documented in depth. It is Microsoft helper/sample code used for console rendering, input, resources, and related XDK support. The rest of the docs only mention ATG where the project calls into it.

## The Short Version

`main.cpp` is the top-level coordinator. It mounts storage aliases, creates the console, asks `showUI()` for a selected game URL and game name, reads `game:\settings.txt`, builds a safe output folder, then calls `getGame()`.

`getGame()` downloads a Vimm archive to `game:\tmp.7z.001`, follows a fallback download domain when needed, extracts the 7z archive, and then either:

- finds and copies an XBLA-style title ID directory, or
- finds an extracted `.iso` / `.iso.001`, extracts the ISO contents with the xiso code, and deletes temporary folders.

Networking goes through `downloadFileHTTPS()`, which parses the URL, initializes XNet/Winsock, builds an `XboxTLSContext`, injects hardcoded trust anchors, resolves DNS, performs a BearSSL TLS 1.2 handshake, sends an HTTP/1.1 GET, and streams the response into either a file or memory buffer.

The project is built around console limitations: no normal OS certificate store, limited memory, FATX/FAT32 file-size limits, Xbox path aliases such as `game:\`, and some awkward filename behavior on USB/FAT32. Most of the custom glue exists to keep large downloads and large archive extraction streaming instead of loading whole files into RAM.
